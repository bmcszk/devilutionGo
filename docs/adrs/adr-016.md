# 016. Networking: loopback default now, protocol lanes decided later

Date: 2026-11-03
Status: Proposed

## Context

We need flexibility across single player, client-client, and client-server, but the original shipped SP and MP on one deterministic core. The catalog (go-libraries.md) holds no networking entries yet; choosing a protocol before the kernel exists would be guesswork.

## Decision

One narrow Transport interface in game/ (command envelopes in/out). Default implementation: in-process loopback - SP uses it, MP later reuses the same wire format. Protocol decisions (turn protocol, prediction, rollback, topology) are explicitly deferred to a dedicated ADR when the first MP slice starts. Candidates recorded, not pinned: plain UDP/TCP relay for LAN; quic-go (~12k stars, pure Go, RFC 9221 unreliable datagrams) for the internet lane.

## Consequences

No premature protocol lock-in; the kernel stays transport-agnostic; catalog entries land only when a lane is decided (ADR-009 process).
