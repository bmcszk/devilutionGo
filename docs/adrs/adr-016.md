# 016. Networking: simple loopback now, protocols later

Date: 2026-11-03
Status: Proposed

## Context

We want the game to support single player, player to player, and player to server later, but we do not need internet play yet. Choosing a protocol before the simulation exists would guess wrong, and undoing it is expensive.

## Decision

The simulation talks to one small interface named Transport that sends and receives command packets. Single player uses an in-process copy of this interface. Multiplayer later reuses the same packets over the network. Details (turn order, client prediction, rollback, who acts as server) wait for their own ADR when the first multiplayer milestone starts. Library picks land in the catalog at the same time (ADR-009). Plain TCP or UDP for LAN and quic-go for internet play are recorded as options, not chosen today.

## Consequences

The simulation stays independent of network code from day one. No protocol or library gets locked in before it is needed.
