# 021. One devkit refresher command

Date: 2026-11-06
Status: Accepted (2026-11-06)

Supersedes in part `docs/adrs/adr-019.md:88-95`.

## Context

ADR-019 kept the fixture refreshers apart and rejected folding them
(`docs/adrs/adr-019.md:88-95`). Its reason was that a fold "would add a dispatch
layer without removing a code path", because the two programs "share no code
today" (`docs/adrs/adr-019.md:90-92`).

That premise no longer holds up. One of the two already became the dispatcher
the fold was said to add: `tools/probe/dunconv/main.go` chose its behaviour from
`args[0]`, with four modes (`dunconv <artifact-dir> <corpus-dir>`, `dpiece`,
`town`, `town-inputs`) and a usage error for anything else. The dispatch layer
exists today. The fold moves it one directory and gives it a name that says what
it does.

The cost ADR-019 counted is still real. Today there were two Go `main`
packages and two rows in the devkit table. The fold deletes one `main`, and the
table keeps one row for the command (`tools/probe/README.md:97-99`).

The two programs still share no source code, and this ADR does not claim they
do. They share a job: read an offline input, write a committed golden through
the same `testsupport` encoder the tests decode with. One command for one job is
the smaller surface.

## Decision

`tools/goldens` is the one devkit refresher command. It is a flat `package
main` with a table of subcommands (`tools/goldens/main.go:36-42`) and one
dispatch path (`tools/goldens/main.go:52-74`):

| Subcommand | Positional paths | What it rewrites |
|---|---|---|
| `dun` | `<artifact-dir> <corpus-dir>` | `internal/testdata/drlg/*.csv` |
| `dpiece` | `<artifact-dir> <corpus-dir>` | `internal/testdata/drlg/dpiece/*.csv` |
| `town` | `<artifact-dir> <corpus-dir>` | `internal/testdata/drlg/town/*.csv` |
| `town-inputs` | `<raw-dun-dir> <corpus-dir>` | `<corpus-dir>/inputs/*.csv` |
| `gamedata` | none | `internal/testdata/gamedata/goldens/*.json` |

The four dungeon forms are the `dunconv` dispatch moved without a behaviour
change. `gamedata` is the former `tools/gamedatagoldens` run body. A wrong name
or a wrong argument count prints one usage line listing all five
(`tools/goldens/main.go:76-84`), so a mistyped command cannot silently refresh
nothing.

## What stays as it is

**The two-binary law.** ADR-020 ships exactly two user-facing binaries
(`docs/adrs/adr-020.md:37`), and fixture refreshers stay out of that set
(`docs/adrs/adr-020.md:55`). `tools/goldens` is test instrumentation, not a
third binary. Nothing under `cmd/` changes.

**The never-ships, never-CI carve-out.** No `go test`, no recipe and no CI job
runs `tools/goldens` outside a refresh (`docs/adrs/adr-019.md:81-84`). A refresh
ends with a normal test run that reads the committed bytes.

**The sim purity gate.** `scripts/lint.sh:94` runs `scripts/simpurity` over the
`internal/game` and `internal/diablo` import graphs. That gate guards a
different class of failure, wall-clock and file io leaking into game code, and
it is not folded into this command.

**The C++ probes.** `tools/probe/dvg_probe.cpp` and its patches build inside the
devilutionX CMake tree (`tools/probe/README.md:17-35`). They are reference
instrumentation in a different build universe and stay where they are. The fold
touches the Go side only, which also means `tools/probe/out/` stays the artifact
staging area both sides use.

## Consequences

**One command to document.** The devkit table in `tools/probe/README.md:97-99`
has one row instead of two, and `just refresh-gamedata-goldens`
(`justfile:53-62`) calls `go run ./tools/goldens gamedata`.

**One place for a new fixture family.** Adding one is a row in the subcommand
table plus a `run` body, not a new `main` package.

**The rejection is recorded, not erased.** ADR-019 keeps its text and gains one
sentence marking the superseded part (`docs/adrs/adr-019.md:97-98`). A reader who
finds the old rejection finds the reason it changed.
