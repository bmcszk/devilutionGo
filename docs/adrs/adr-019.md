# 019. One conversion surface

Date: 2026-11-05
Status: Accepted (2026-11-05)

## Context

The project has one conversion job: retail Diablo files must become the form
the game reads. MPQ contents into an assets dir, game tables into CSV, asset
lists into YAML, old saves into SQLite, `diablo.ini` carried over. ADR-014
decided this would be one program, `devilutionGo-migrate`, with three
subcommands, so the MPQ decode code exists once
(`docs/adrs/adr-014.md:8-12`).

The tree does not match it yet. Five commands live under `cmd/` and four
artifacts under `tools/probe/` (`docs/research/dg-conversion-inventory.md`).
Two of them are conversion programs in practice:

* `devilutionGo-migrate assets` extracts archives, writes the CSV tables and
  writes `manifest.yaml` (`cmd/devilutionGo-migrate/assets.go:260-263`). It
  copies CEL and CL2 byte for byte instead of converting them
  (`cmd/devilutionGo-migrate/extract.go:248-252`).
* `dgo-assets` checks a graphics inventory and converts CEL, CL2 and PCX to CLX
  (`cmd/dgo-assets/internal/cli/cli.go:54-73`). The conversion code itself
  already lives in `internal/assets` (`internal/assets/cel_to_clx.go`,
  `cl2_to_clx.go`, `pcx_to_clx.go`), so `dgo-assets` is a thin command over a
  shared library.

The split costs more than a second binary. Both writers call their file
`manifest.yaml` with different schemas:
`cmd/devilutionGo-migrate/manifest.go:85-92` writes `archives` plus `files`,
while `internal/assets/manifest/manifest.go:91-96` expects `entries` with a
loader line. Run `dgo-assets check` on a file the migration tool wrote and it
decodes zero entries and exits 0 (`cli.go:118-131`). The coverage gate fails
open on the wrong file. Nothing invokes `dgo-assets` today: no recipe, no
`go:generate`, no test outside its own package.

## Decision

`devilutionGo-migrate` is the one conversion program. Every other conversion
surface either goes away or is documented as test instrumentation. The old
`dgo-assets` command name goes away the same way `devilutionGo-import` did in
ADR-003 (`docs/adrs/adr-003.md:4`). Nothing calls it, so there is no deprecation
window.

The `assets` subcommand grows two things and keeps its flags:

1. **Conversion.** An extracted `.cel`, `.cl2` or `.pcx` record whose inventory
   entry carries frame widths is converted to `.clx` with the existing
   `internal/assets` converters. A record with no width data keeps today's
   copy-as-is behavior and stays marked `format: cel` or `format: cl2`, because
   frame dimensions live in the caller's tables upstream (`extract.go:249-251`).
2. **`assets verify`.** A nested subcommand, not a flag. It reads the inventory,
   resolves every path under a root, prints `missing <path> (requested by
   <loader>)` per miss, and exits 1 on any miss. It is nested because it needs
   no archives, while `assets` itself refuses to run without them
   (`assets.go:129-140`). A `--verify` flag would have to bypass archive
   resolution and would mix two jobs in one flag set. Nesting also keeps
   ADR-014's three top-level subcommands intact.

The two YAML files get different names. `manifest.yaml` stays the extraction
record: what was extracted, from which archive, with which hash
(`cmd/devilutionGo-migrate/manifest.go:20-92`). The graphics list becomes
`assets/inventory.yaml`: what the renderer requires, with the loader call site
and the width source (`internal/assets/manifest/manifest.go:55-73`). A record
cannot express a requirement. Merging them would either add hand-written rows
to a hashed idempotency summary or drop the loader lines the coverage check
prints. Both stay YAML under ADR-013 (`docs/adrs/adr-013.md:12`);
`internal/assets/manifest` stays the model.

## Test instrumentation is not part of the one program

The probe tooling looks like more conversion programs. It is not. It produces
committed fixtures offline, once, against pinned devilutionX
(`tools/probe/README.md:1-5`). Test instrumentation never ships and never runs
in `go test` or CI, per the zero-dependency rule in `AGENTS.md` section 6. This
carve-out is explicit so nobody re-opens it.

* `tools/probe/dvg_probe.cpp` and its three patches stay as they are. They are
  reference instrumentation: dump only, pinned to commit `ca91d778f`, adding no
  game logic (`README.md:37-48`).
* `tools/probe/dunconv`, `tools/probe/affix_probe` and
  `cmd/gamedatagoldens` are fixture refreshers. They are not conversion tools
  and they are not for users.

The three refreshers get one documented home instead of a new program. Add a
devkit section to `tools/README.md` that lists each refresher, its input, its
output and the gate that checks the result. Keep the programs where they
are. Folding `dunconv` and `gamedatagoldens` into a single `tools/goldens`
command would add a dispatch layer without removing a code path: they share
no code today (`tools/probe/dunconv/main.go:12` uses
`internal/diablo/testsupport`, `cmd/gamedatagoldens/main.go:6` uses
`internal/testsupport/parity`), and one of them sits with the probe artifacts
it consumes. The cost is not the number of binaries, it is not knowing which
one to run. One README solves that.

## Consequences

**Users see one tool.** `devilutionGo-migrate assets` extracts, converts and
records in one pass, and `devilutionGo-migrate assets verify` checks the result
without needing the retail archives.

**One parsing path per format.** CEL, CL2 and PCX each have one converter in
`internal/assets`, called by one command. The assets dir and the coverage check
read the same inventory file.

**Tests move, guarantees stay.** The convert and encoder tests stay in
`internal/assets` unchanged. `cmd/dgo-assets/internal/cli/cli_test.go` splits
into two files under `cmd/devilutionGo-migrate`: `assets_verify_test.go` keeps
the "missing entry prints its loader line, exit 1" case (`cli_test.go:17`), and
`assets_convert_test.go` keeps the "convert output equals the converter golden"
case (`cli_test.go:122`). The fixtures under `internal/testdata/gfx` do not
move. Add one test for the defect this ADR closes: verification against an
extraction record must fail loudly instead of reporting zero entries.

**Removed.** `cmd/dgo-assets` and its `internal/cli` package. The writer name
`dgo-assets` in `internal/assets/manifest/manifest.go:28`.

**Renamed.** The graphics list file, from `manifest.yaml` to
`assets/inventory.yaml`, in the writer, the reader defaults
(`cli.go:104,:138`) and the model comment.

**Not decided here.** Whether `assets` gains family enumeration (bean
devilGo-l5fp) and whether the built assets dir gets embedded per ADR-005.
Neither leg exists today (`docs/research/dg-conversion-inventory.md`).
