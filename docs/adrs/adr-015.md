# 015. Deterministic command/event simulation kernel

Date: 2026-11-03
Status: Proposed

## Context

The original engine is deterministic per-tick lockstep: only commands cross the wire, and per-tick AI seeds keep nodes identical. ADR-002 demands identical algorithms and RNG behavior; ADR-008 fixes the layer layout (engine/, game/); ADR-010 gates parity. Simulation must be inspectable headlessly and reusable for other ARPG ideas (milestone law).

## Decision

Fixed-tick kernel inside game/ (per ADR-008, no new layer): state advances only via ordered command application; handlers emit events; client-predicted events are presentation-only, never truth. Seeded RNG streams per concern (drops, per-tick AI seeds, attacks, durability) mirror the original. Fixed-point math only - float64 banned in simulation code. CI-enforced purity: no wall clock, no goroutines, no map iteration in sim packages. Presentation is a read-only event consumer. Watermill (GoChannel backend, ~10k stars, MIT) carries command/event dispatch in-process; replay golden tests with per-tick state checksums extend ADR-010.

## Consequences

Single-player becomes multiplayer with one peer; replay, desync detection and headless testing fall out of determinism; the event log is simultaneously netcode, replay and debug trace.
