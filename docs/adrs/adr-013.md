# 013. Game tables are CSV; asset lists are YAML; settings stay INI

Date: 2026-11-03
Status: Proposed

## Context

Diablo 1 stores its game data (monsters, items, spells, levels) as text tables inside the MPQ archives. ADR-002 requires the port to keep the same data values. ADR-004 says user settings stay in diablo.ini. ADR-003 says saves go to SQLite. We still need one clear home for the extracted game data and for the asset lists.

## Decision

Game data tables are CSV files, one file per table, with the same columns as the original tables. The migration tool writes them (ADR-014). No one edits them by hand; when data must change, the tool or its source data changes first. Flat lists that describe files and tools (asset lists, pack indexes, tool settings) are YAML files. User settings stay in diablo.ini (ADR-004). Saves stay in SQLite (ADR-003). The Go code checks the values it reads from these files (allowed ranges, allowed names), and tests cover those checks.

## Consequences

Game balance cannot change by hand, so the port keeps parity with the original data. Tests catch bad values at load time. A different game can reuse the same CSV and YAML pattern with its own tables.
