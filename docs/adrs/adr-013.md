# 013. Registries are CSV data; manifests YAML; settings stay INI

Date: 2026-11-03
Status: Proposed

## Context

ADR-002 pins all data values to parity; ADR-004 keeps user settings in diablo.ini; ADR-003 puts saves in SQLite; ADR-005 extracts MPQ data to loose files. Game registries (monsters, items, affixes, spells, levels) currently exist as C arrays and MPQ TXT exports. We need one governed home for extracted data that also generalizes to non-Diablo content.

## Decision

Registry tables are CSV under the extracted-data layout: one file per table, columns matching the canonical TXT exports, generated by the migration tool - never hand-edited. Flat pipeline metadata (asset manifests, pack indexes, tool config) is YAML. User settings remain diablo.ini per ADR-004 and never move to YAML/SQLite. Parsing and range/enum validation rules live in Go code, tested against the tables.

## Consequences

Balance data cannot drift by hand; regeneration is idempotent. A non-Diablo game reuses the same CSV+manifest pattern with its own tables.
